## 1. Context management & compaction

### 1.1 Token budget model (`services/compact/autoCompact.ts`)

- Effective context window = model context window − `min(modelMaxOutputTokens, 20_000)` (`MAX_OUTPUT_TOKENS_FOR_SUMMARY = 20_000`, line 30; comment: "Based on p99.99 of compact summary output being 17,387 tokens").
- Env override `CLAUDE_CODE_AUTO_COMPACT_WINDOW` clamps the context window (`Math.min(contextWindow, parsed)`).
- **Auto-compact trigger threshold = effectiveContextWindow − 13,000** (`AUTOCOMPACT_BUFFER_TOKENS = 13_000`, line 62). So it's a fixed token buffer, not a % of the window. Test override: `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (0–100, takes min of percentage threshold and the default threshold).
- Warning threshold = trigger − 20,000 more tokens (`WARNING_THRESHOLD_BUFFER_TOKENS = 20_000`); same for error threshold. `calculateTokenWarningState()` computes `percentLeft` against the trigger threshold.
- Blocking limit (manual /compact refused) = effective window − `MANUAL_COMPACT_BUFFER_TOKENS = 3_000` (lines 65, 123–136). Override: `CLAUDE_CODE_BLOCKING_LIMIT_OVERRIDE`.
- Token counting: `tokenCountWithEstimation(messages)` — uses last API response's real usage plus estimation for newer messages (utils/tokens.ts).
- **Disable switches**: env `DISABLE_COMPACT` (all compaction), `DISABLE_AUTO_COMPACT` (auto only, manual /compact still works), plus user config `autoCompactEnabled` (line 147–158).
- Recursion guards: never auto-compact for `querySource === 'session_memory' | 'compact'` (and ant-only `marble_origami`).
- **Circuit breaker**: `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3` consecutive failures → stop retrying that session (motivating comment: sessions with 50–3,272 futile attempts wasting ~250K API calls/day).

### 1.2 Compaction pipeline (`services/compact/compact.ts`)

`compactConversation()` flow:
1. Run **PreCompact hooks** (`executePreCompactHooks`, trigger `auto|manual`); hook-provided `newCustomInstructions` merged after user instructions (`mergeHookInstructions`).
2. Send the summary request via `streamCompactSummary`:
   - **Default path reuses the main conversation's prompt cache**: `runForkedAgent` (a forked agent sharing cache-key params: system, tools, model, message prefix, thinking config) with `maxTurns: 1`, `skipCacheWrite: true`, and tools denied via `createCompactCanUseTool()` (compaction agent must only emit text). Feature flag `tengu_compact_cache_prefix` defaults **true** (3P default too; Jan-2026 experiment: non-shared path was 98% cache miss).
   - **Fallback path**: plain streaming call with a minimal system prompt ("You are a helpful AI assistant tasked with summarizing conversations."), thinking disabled, tools = `[FileReadTool]` (plus `ToolSearchTool` + MCP tools when tool-search is enabled, all deduped by name), `maxOutputTokensOverride = min(COMPACT_MAX_OUTPUT_TOKENS, modelMax)`.
   - Before sending: `stripImagesFromMessages` (image/document blocks → `[image]`/`[document]` text markers, including inside tool_results), `stripReinjectedAttachments`, `getMessagesAfterCompactBoundary`.
   - **Prompt-too-long retry** (CC-1180): if the compact request itself PTLs, `truncateHeadForPTLRetry` drops oldest API-round groups (grouped by `groupMessagesByApiRound`) until the parsed token gap is covered (fallback: drop 20% of groups); up to `MAX_PTL_RETRIES = 3`; prepends synthetic user marker `[earlier conversation truncated for compaction retry]` if the slice starts with an assistant message.
3. On success: snapshot `context.readFileState`, **clear `readFileState` and `loadedNestedMemoryPaths`**; intentionally do NOT reset `sentSkillNames` (avoid ~4K-token skill_listing re-injection).
4. Build post-compact attachments (see 1.4).
5. Run **SessionStart hooks** with source `'compact'`.
6. Emit compact boundary marker (`createCompactBoundaryMessage(trigger, preCompactTokenCount, lastMessageUuid)`) carrying `compactMetadata.preCompactDiscoveredTools` (deferred/tool-search tool names survive so their schemas keep being sent post-compact).
7. Summary message = user message flagged `isCompactSummary: true` (content from `getCompactUserSummaryMessage`).
8. Run **PostCompact hooks**; re-append session metadata (`reAppendSessionMetadata()`, keeps custom title within the 16KB tail window `readLiteMetadata` reads for --resume display); reset prompt-cache-break detection baseline.

### 1.3 The summarization prompt (`services/compact/prompt.ts`)

Three variants (BASE / PARTIAL / PARTIAL_UP_TO), all wrapped in an aggressive `NO_TOOLS_PREAMBLE` ("Tool calls will be REJECTED and will waste your only turn") and a `NO_TOOLS_TRAILER`.

The BASE prompt asks for `<analysis>` (drafting scratchpad) then `<summary>` with **9 fixed sections**:
1. Primary Request and Intent
2. Key Technical Concepts
3. **Files and Code Sections** — "Enumerate specific files and code sections examined, modified, or created… include full code snippets"
4. Errors and fixes — "Pay special attention to specific user feedback"
5. Problem Solving
6. **All user messages** — "List ALL user messages that are not tool results. These are critical"
7. **Pending Tasks** — explicitly asked-for work
8. Current Work — with file names/snippets
9. Optional Next Step — must quote verbatim recent conversation to avoid drift.

Partial variants scope to "recent messages" or (up_to) instruct the model the summary will be *preceded* by kept newer messages (section 9 becomes "Context for Continuing Work"). Custom instructions from `/compact <args>` are appended as "Additional Instructions:".

Post-processing (`formatCompactSummary`): the `<analysis>` block is stripped before injection; `<summary>` tags become a `Summary:` header.

**Re-injection**: `getCompactUserSummaryMessage` wraps it as: "This session is being continued from a previous conversation that ran out of context. The summary below covers the earlier portion of the conversation." + formatted summary + "If you need specific details from before compaction (like exact code snippets, error messages, or content you generated), read the full transcript at: <transcriptPath>" + (if a tail was preserved) "Recent messages are preserved verbatim." + (for auto-compact, `suppressFollowUpQuestions`) "Continue the conversation from where it left off without asking the user any further questions. Resume directly — do not acknowledge the summary…".

New message order post-compact (`buildPostCompactMessages`): boundaryMarker → summaryMessages → messagesToKeep → attachments → hookResults.

### 1.4 What survives compaction (post-compact restore budget, `compact.ts` lines 122–130)

- `POST_COMPACT_MAX_FILES_TO_RESTORE = 5` recently-read files (from readFileState, most-recent-first), capped by `POST_COMPACT_TOKEN_BUDGET = 50_000` total and `POST_COMPACT_MAX_TOKENS_PER_FILE = 5_000` per file. Files already visible as Read results in the preserved tail are skipped (dedup via `collectReadToolFilePaths`).
- Invoked skills re-injected as `invoked_skills` attachment: most-recent-first, truncated to `POST_COMPACT_MAX_TOKENS_PER_SKILL = 5_000` each (head kept, marker tells the model it can Read the skill path), total budget `POST_COMPACT_SKILLS_TOKEN_BUDGET = 25_000`.
- Plan file re-attached (`plan_file_reference`) if a plan exists; plan-mode instructions re-attached if still in plan mode.
- Async/background agents re-announced as `task_status` attachments so the model doesn't re-spawn duplicates (skips `retrieved`/`pending`/self).
- Deferred-tools / agent-listing / MCP-instructions delta attachments re-announced against an empty history (i.e., full set re-announced).
- Excluded from restore: plan files and all CLAUDE.md-family memory files (`shouldExcludeFromPostCompactRestore`).

### 1.5 /compact command (`commands/compact/compact.ts`)

- Projects messages through `getMessagesAfterCompactBoundary` first (snipped messages aren't summarized).
- Priority order: (1) **session-memory compaction** if no custom instructions (`trySessionMemoryCompaction` — experimental, `services/compact/sessionMemoryCompact.ts`); (2) ant-only reactive compact; (3) traditional path: `microcompactMessages` first (opportunistic pruning), then `compactConversation` with custom instructions = args.
- Partial compact (`partialCompactConversation`, used by a message-selector UI): directions `'from'` (summarize after pivot, keep prefix — cache preserved) and `'up_to'` (summarize before pivot, keep suffix — cache broken). Boundary annotated with `preservedSegment {headUuid, anchorUuid, tailUuid}` so the transcript loader can relink parentUuid chains.
- Micro-compaction: `services/compact/microCompact.ts` + `apiMicrocompact.ts` **[unverified — not read]**.

## 2. CLAUDE.md / memory-file loading (`utils/claudemd.ts`)

Header comment states the order explicitly (files loaded in reverse priority — later = higher priority):

1. **Managed** (enterprise): `/etc/claude-code/CLAUDE.md` (`getMemoryPath('Managed')`) + managed `.claude/rules/*.md`.
2. **User**: `~/.claude/CLAUDE.md` + `~/.claude/rules/*.md` (only if `userSettings` source enabled).
3. **Project**: walked from filesystem root **down to CWD**; in each dir: `CLAUDE.md`, `.claude/CLAUDE.md`, and recursively all `.md` under `.claude/rules/` (only if `projectSettings` enabled). Nested-worktree dedup: checked-in files from the main repo outside the worktree are skipped; `CLAUDE.local.md` still loads.
4. **Local**: `CLAUDE.local.md` in each dir root→CWD (`localSettings` enabled).
5. **AutoMem** entrypoint (`<autoMemPath>/MEMORY.md`, truncated) and **TeamMem** entrypoint appended last if enabled.
- Additional directories (`--add-dir`): CLAUDE.md + `.claude/CLAUDE.md` + rules loaded only when env `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` is truthy (default off).

Mechanics:
- **@include directive**: `@path`, `@./rel`, `@~/home`, `@/abs` (bare `@path` = relative). Extracted via marked lexer **only from leaf text nodes** (never inside code blocks/codespans; HTML-comment residue is scanned). `MAX_INCLUDE_DEPTH = 5`; circular refs blocked by processed-path set; includes are emitted **before** the including file (comment: "main file first (parent before children)" — i.e., included files follow the parent in the result list); non-existent files silently ignored; external (outside CWD) includes require approval (`hasClaudeMdExternalIncludesApproved`) unless `forceIncludeExternal`.
- Only text extensions allowed (large `TEXT_FILE_EXTENSIONS` allowlist — md/txt/json/yaml/js/ts/py/go/rs/java/c/cpp/sh/… — prevents binary loads).
- Frontmatter: `paths:` (comma or list; `/**` suffix stripped; all-`**` = unconditional) turns a `.claude/rules/*.md` file into a **conditional rule** matched with the `ignore` glob library against the target file path (Project rules relative to the dir containing `.claude`; Managed/User relative to original CWD). Conditional rules load lazily per-file via `getManagedAndUserConditionalRules` / `getMemoryFilesForNestedDirectory` (nested memory loading).
- Block-level HTML comments `<!-- … -->` stripped (marked lexer, CommonMark html blocks; code spans/fences preserved; unclosed comments kept).
- `claudeMdExcludes` setting (picomatch, symlink/realpath-aware) can exclude files by path for User/Project/Local.
- `MAX_MEMORY_CHARACTER_COUNT = 40_000` — used by `getLargeMemoryFiles` to warn.
- Injection format (`getClaudeMds`): `MEMORY_INSTRUCTION_PROMPT` ("…These instructions OVERRIDE any default behavior and you MUST follow them exactly as written.") then per file: "Contents of <path><description>:\n\n<content>" where description distinguishes "(project instructions, checked into the codebase)" / "(user's private project instructions, not checked in)" / "(user's private global instructions for all projects)" / auto-memory/team variants.
- Memoized (`getMemoryFiles`); two invalidation flavors: `clearMemoryFileCaches()` (silent) and `resetGetMemoryFilesCache(reason)` (also re-fires `InstructionsLoaded` hooks with reason `session_start|compact|include…`).
- `isMemoryFilePath()` = basename `CLAUDE.md`/`CLAUDE.local.md` anywhere + `.md` under `*/.claude/rules/` — used to track memory-file edits via readFileState.

## 3. Auto-memory (memdir/)

- **Enable chain** (`memdir/paths.ts isAutoMemoryEnabled`, enabled by default): `CLAUDE_CODE_DISABLE_AUTO_MEMORY` env → `CLAUDE_CODE_SIMPLE` (--bare) off → CCR remote without `CLAUDE_CODE_REMOTE_MEMORY_DIR` off → `autoMemoryEnabled` settings key → on.
- **Directory** (`getAutoMemPath`): override `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE` env → `autoMemoryDirectory` settings (policy/flag/local/user only — projectSettings deliberately excluded for security: "a malicious repo could otherwise set autoMemoryDirectory: '~/.ssh'") → `<memoryBase>/projects/<sanitized-canonical-git-root>/memory/` where memoryBase = `CLAUDE_CODE_REMOTE_MEMORY_DIR` or `~/.claude`. Canonical git root ⇒ all worktrees share one memory dir.
- **Design**: two-step save — each memory is its own topic file (e.g. `user_role.md`) with frontmatter (name/description/type), then a one-line pointer `- [Title](file.md) — one-line hook` in `MEMORY.md`. **MEMORY.md is the index, not a memory**; it is always loaded into context (via claudemd.ts) and truncated at `MAX_ENTRYPOINT_LINES = 200` lines / `MAX_ENTRYPOINT_BYTES = 25_000` bytes with a warning naming the cap ("Keep index entries to one line under ~200 chars; move detail into topic files").
- Closed **four-type taxonomy**: user / feedback / project / reference (memoryTypes.ts); "content derivable from the current project state (code patterns, architecture, git history)" is explicitly excluded; do-not-save section included in prompt.
- The prompt (in system prompt via `loadMemoryPrompt`) tells the model the directory **already exists** ("do not run mkdir or check for its existence" — harness calls `ensureMemoryDirExists`), plus a "Memory and other forms of persistence" section contrasting memory (future conversations) vs plans (current-task alignment) vs tasks (current-conversation progress).
- **Recall/search**: `buildSearchingPastContextSection` (flag-gated) instructs grep over `<autoMemDir>/**/*.md` then session transcripts `<projectDir>/**/*.jsonl` as last resort. `findRelevantMemories.ts` does prefetch/relevance ranking surfaced as attachments **[unverified — not read]**.
- **Write paths**: main agent writes directly via Write tool (full instructions always in prompt); a background extract-memories fork (`services/extractMemories/`, flag `tengu_passport_quail`) catches anything missed at turn end **[unverified]**. KAIROS assistant-mode variant: append-only daily logs `logs/YYYY/MM/YYYY-MM-DD.md`, nightly /dream distills into topic files + MEMORY.md. Team memory lives at `<autoMemPath>/team` (ant-gated `TEAMMEM`).
- `isAutoMemPath()` grants a filesystem write carve-out (bypasses DANGEROUS_DIRECTORIES) but is hardened against `~`, roots, UNC, null bytes (validateMemoryPath).

## 4. MCP (`services/mcp/`)

### 4.1 Config sources & precedence (`config.ts getClaudeCodeMcpConfigs`)

- **Scope enum** (`types.ts`): `local | user | project | dynamic | enterprise | claudeai | managed`.
- **Enterprise exclusive**: if `<managed-path>/managed-mcp.json` exists (`getEnterpriseMcpFilePath()`), *only* those servers are used (after policy filtering); everything else ignored.
- Otherwise merge order = **plugin < user < project(approved) < local** (Object.assign order, line 1231–1238). Plugin servers are namespaced `plugin:<name>:<server>` so they never key-collide; content-signature dedup suppresses plugin servers duplicating a manual server (signature = `stdio:<json command array>` or `url:<unwrapped URL>`; env/headers ignored).
- **Project `.mcp.json` servers require user approval** before use (`getProjectMcpServerStatus(name) === 'approved'`).
- `dynamic` scope = servers injected at runtime (SDK `--mcp-config`); `claudeai` scope = claude.ai connectors (fetched, deduped against enabled manual servers by URL/command signature; manual wins).
- Policy: `allowedMcpServers`/`deniedMcpServers` in settings — entries by exact `serverName`, by `serverCommand` array (stdio), or by `serverUrl` glob pattern (wildcard `*`, e.g. `https://*.example.com/*`). `allowManagedMcpServersOnly` policy restricts allowlist to managed settings; denylists always merge all sources. Env vars in config strings expanded (`envExpansion.ts`).

### 4.2 Config file shape (`types.ts` McpJsonConfigSchema)

`.mcp.json` / user config = `{ "mcpServers": { "<name>": <McpServerConfig> } }` where McpServerConfig is one of:

| type | fields |
|---|---|
| `stdio` (default, `type` optional) | `command` (min 1 char), `args[]`, `env{}` |
| `sse` | `url`, `headers{}`, `headersHelper`, `oauth{clientId, callbackPort, authServerMetadataUrl (https), xaa}` |
| `http` (streamable) | same as sse |
| `ws` | `url`, `headers{}` |
| `sdk` | `name` (in-process SDK server) |
| internal-only | `sse-ide` (url, ideName), `ws-ide` (url, ideName, authToken), `claudeai-proxy` (url, id) |

Connection states modeled as: `connected` (client + capabilities + serverInfo + instructions) / `failed` / `needs-auth` / `pending` / `disabled`.

### 4.3 Transports (`client.ts`)

- stdio → `StdioClientTransport`; sse → `SSEClientTransport` (long-lived EventSource fetch deliberately NOT timeout-wrapped; 60-s timeout wrapper only on POSTs/auth); http → `StreamableHTTPClientTransport` (ensures MCP `Accept` header); ws/ws-ide → WebSocket (Bun or Node client, subprotocol `mcp`, `X-Claude-Code-Ide-Authorization` header for IDE); sdk → in-process (`InProcessTransport.ts`); `SdkControlTransport.ts` for SDK control protocol; `claudeai-proxy` → HTTP with claude.ai OAuth bearer + 401 refresh retry.
- Custom fetch middleware per transport: static+dynamic headers (`getMcpServerHeaders`, incl. `headersHelper`), UA `getMCPUserAgent()`, proxy options, timeout wrapper, "step-up" 403 detection.
- **OAuth**: `auth.ts` `ClaudeAuthProvider` per server (PKCE; sensitive params state/nonce/code_challenge/code_verifier/code redacted in logs; local callback on configurable `callbackPort` via `oauthPort.ts`). Failure → `McpAuthError` → connection state `needs-auth`, cached in `~/.claude/mcp-needs-auth-cache.json` for 15 min (`MCP_AUTH_CACHE_TTL_MS`) so batched startup doesn't re-prompt. **XAA (Cross-App Access, SEP-990)**: per-server `oauth.xaa: true`; one IdP OIDC+PKCE browser login (id_token cached in keychain by issuer) then RFC 8693 token exchange — no per-server browser pop. Tool-call 401s surface `McpAuthError` to flip status to needs-auth.
- Connection manager: `MCPConnectionManager.tsx` + `useManageMCPConnections` (React state); `officialRegistry.ts` (registry validation), `channelAllowlist/channelPermissions/channelNotification` (plugin "channels"), `vscodeSdkMcp.ts` (IDE bridge).

### 4.4 Tool naming & discovery

- **Fully qualified name = `mcp__<normalizedServer>__<normalizedTool>`** (`mcpStringUtils.ts getMcpPrefix/buildMcpToolName`; `normalizeNameForMCP` sanitizes chars). Parse: `mcpInfoFromString` splits on `__` (server may not contain `__`; tool parts re-joined to preserve `__` in tool names). Permission rules match the fully qualified name; wildcards like `mcp__playwright__*` work.
- Discovery: tools, resources, prompts enumerated from the connected client (`ServerResource = Resource & {server}`; `resources` map in MCPCliState); server `instructions` field carried on the connection and re-announced via `getMcpInstructionsDeltaAttachment` after compaction.
- MCP skills: `mcpSkillBuilders.ts` allows MCP servers to provide skills **[unverified]**.

## Vexa implications

- **Auto-compact is a token-buffer threshold, not a %**: trigger at `effectiveWindow − 13k`, where effective = window − min(maxOutput, 20k) reserved for the summary. Replicate the reserve; expose env overrides (`VEXA_AUTOCOMPACT_PCT_OVERRIDE`-style) for testing.
- **Reuse the parent's prompt cache when compacting**: run the summarizer as a forked agent with identical system/tools/prefix params, tools denied, maxTurns 1, no cache write; fall back to a bare "summarizing assistant" streaming call with images stripped. This is the single biggest cost lever in the whole pipeline.
- **Compaction prompt = 9 fixed sections** (intent, concepts, files+snippets, errors+user feedback, problem solving, all user messages, pending tasks, current work, next step with verbatim quotes) wrapped in an explicit "no tools or you fail" preamble; strip the `<analysis>` scratchpad before injecting, and inject as a user message with the transcript path so the model can grep the full history.
- **Post-compact re-hydration is budgeted, not unlimited**: 5 most-recent read files (50k total, 5k/file), invoked skills truncated head-first (5k each, 25k total), plan + plan-mode + background-agent status + deferred-tool/agent/MCP deltas re-announced; CLAUDE.md files deliberately not restored.
- **Compaction must be idempotent against message identity**: clear readFileState, keep a boundary message carrying preCompactDiscoveredTools, thread `preservedSegment` metadata so the on-disk parentUuid chain can be relinked, and re-append session metadata to stay in the tail window.
- **CLAUDE.md pipeline**: 4 instruction layers (managed→user→project-walk→local) + conditional `paths:` rules + `@include` (depth ≤ 5, text-extension allowlist, code-span safe) + HTML-comment stripping + 40k-char warning; inject with per-file provenance labels and an "OVERRIDE any default behavior" preamble.
- **Auto-memory**: index file (MEMORY.md, ≤200 lines/25KB, always loaded) + per-topic files with frontmatter and a closed type taxonomy; memory dir keyed by canonical git root so worktrees share; guarantee directory existence so the model never mkdirs.
- **MCP**: ship stdio + HTTP-streamable (+SSE for legacy) first; config scopes with clear precedence (enterprise exclusive → user → approved project `.mcp.json` → local), signature-based dedup, `mcp__server__tool` naming, per-server OAuth (PKCE + needs-auth cache so startup isn't blocked), and policy allow/deny by name/command/URL-glob.
- **Skills/commands unify as markdown+frontmatter**: load frontmatter only at startup (token-cheap), full body on invocation; support `allowed-tools`, `disable-model-invocation`, `paths` gating, and re-invoke survivors post-compaction with per-skill truncation.
- **Subagents**: separate agentId/context/permissions/plans per task; results retrieved explicitly rather than auto-injected; background agents survive compaction as `task_status` attachments to prevent duplicate spawns; one `runForkedAgent` primitive should serve subagents, compaction, and memory-extraction forks alike.
